# ANIMAL LEAGUE 본선 토너먼트 웹앱 — 개발 명세

2026 LIKELION UNIV. 14th Hackathon 본선(**8/25, 코엑스 마곡**)에서 사용할 심사·브래킷 운영 도구.
디자인은 기존 디자인 에셋(브랜드 컬러, 폰트, 캐릭터 일러스트)을 적용하므로, 이 문서는 **기능·데이터·로직**에 집중한다.

> 이 문서가 요구사항의 단일 출처다. 구현 판단이 갈릴 때는 여기를 먼저 본다.
> 진행 상황과 다음 작업은 [HANDOFF.md](./HANDOFF.md) 참고.

## 1. 개요

하나의 웹앱, 역할별 3개 화면.

| 모드 | 사용자 | 기기 | 핵심 기능 |
|------|--------|------|-----------|
| **스크린** (viewer) | 참가자 전원 + 무대 프로젝터 | 대형 스크린, 개인 폰 | 브래킷 실시간 표시, LIVE 표시, 결과 공개 연출, 우승 화면 |
| **심사** (judge) | 심사위원 또는 간사 | 태블릿 / 폰 / 노트북 | 승자 선택 + 코멘트 제출 (**점수 입력 없음**) |
| **운영** (admin) | 운영팀 | 노트북 | 팀 관리, 경기 시작/종료, 집계 열람, 결과 공개, 대진 추첨, 초기화 |

**접근 제어** — 심사 화면은 심사 코드, 운영 화면은 운영 PIN으로 입장. 스크린은 무제한 공개.
코드·PIN은 운영 화면에서 변경 가능.

## 2. 토너먼트 규칙 (행사 규정 기반 — 변경 불가)

- 본선 **8팀** = 트랙별 2팀 × 4트랙 (`SJF` / `AAC` / `LIKELION` / `OPEN`).
- **라운드 1**: 1:1 × 4경기, **같은 트랙 2팀끼리** 대결. 발표 5분 + 공통 Q&A 8분.
- **라운드 2**: 1:1 × 2경기, **트랙 간 랜덤 매칭**. 라이브 시연 3분 + 기술 Q&A 5분.
  - R1 승자는 트랙별 1팀씩이므로, 4팀을 무작위로 짝지으면 자동으로 트랙 간 매칭이 된다. **별도 제약 불필요.**
- **결선**: 단판. 라스트 어필 100초 + 심사위원 합의 100초.
- 각 경기 종료 후 진출팀 즉시 발표 → 운영자의 "결과 공개" 액션이 곧 발표다.
- 라운드 2에서 **시연 장애** 발생 시 제출한 시연 영상으로 대체 가능하되 실현 가능성(20점) 항목에 반영
  → 심사 화면에 팀별 "영상 대체 진행" 체크박스를 두고 기록으로 남긴다.

## 3. 심사 방식 (확정된 결정 사항)

- **승자 선택 + 코멘트만.** 기준별 점수 입력 없음. 모든 라운드 동일.
- **심사위원 명단제** (2026-08-17 결정): 운영 화면에 심사위원 이름을 미리 등록하고,
  **명단에 없는 명의의 제출은 서버가 거부**한다. 심사 코드가 새어도 가짜 표가 집계에 못 섞인다.
  - 심사 화면 입장: 심사 코드 검증 → **명단에서 본인 이름 선택** (직접 타이핑 없음 → 오타·표기 흔들림 차단)
  - 명단은 공개 상태에 포함하지 않는다. 코드 검증을 통과한 요청에만 내려준다
  - 동명이인은 명의가 충돌하므로 등록 시 구분자를 붙인다 (예: "김OO A")
- 입력 주체는 양쪽 지원:
  1. 심사위원이 각자 기기로 직접 제출
  2. 간사 1명이 **대리 입력 모드**를 켜고 심사위원 명의를 **명단에서 지정**해 대신 제출
- 제출은 **결과 공개 전까지 재제출 = 덮어쓰기** (같은 명의 기준).
  - 명의 키(`judgeSlug`)는 이름을 NFC 정규화 + 공백 제거 + 소문자화한 값
  - **live 가 아닌 경기의 제출은 서버가 거부** (공개 직후 지연 도착한 제출이 기록을 바꾸는 것 방지)
  - 제출 시각(ts)은 서버가 찍는다. 이름 30자·코멘트 500자 서버 측 제한
- 심사위원 상호 간 표는 **비공개**. 집계(득표수·코멘트·영상 대체 플래그)는 운영 화면에서만 열람.
- **동표 시 시스템이 자동 결정하지 않는다.** 운영자 화면에 동표 경고만 표시하고,
  사전 합의된 규칙(심사위원장 캐스팅보트 등)으로 운영자가 수동 결정.

## 4. 데이터 모델

### 4.1 전역 상태 (단일 문서, 운영자만 쓰기)

```jsonc
{
  "teams": [ // 정확히 8개, index 가 팀 ID
    { "emoji": "🦁", "school": "OO대", "team": "팀명", "track": "SJF" }
    // track ∈ SJF | AAC | LIKELION | OPEN
    // 실제 에셋 적용 시 emoji 대신 캐릭터 이미지 키로 교체 가능
  ],
  "matches": [
    // votes: 결과 공개 시점의 익명 표 (§6.1 투표 오픈 연출). 공개 전 null,
    //        공개 시 서버가 명의를 떼고 순서를 셔플해 저장 — §3 표 비공개 원칙 유지
    { "id": "R1-1", "round": 1, "a": 0,    "b": 1,    "status": "ready", "winner": null, "votes": null },
    { "id": "R1-2", "round": 1, "a": 2,    "b": 3,    "status": "ready", "winner": null },
    { "id": "R1-3", "round": 1, "a": 4,    "b": 5,    "status": "ready", "winner": null },
    { "id": "R1-4", "round": 1, "a": 6,    "b": 7,    "status": "ready", "winner": null },
    { "id": "R2-1", "round": 2, "a": null, "b": null, "status": "ready", "winner": null }, // 추첨 전 null
    { "id": "R2-2", "round": 2, "a": null, "b": null, "status": "ready", "winner": null },
    { "id": "F",    "round": 3, "a": null, "b": null, "status": "ready", "winner": null }
  ],
  "judges": [], // 심사위원 명단 (§3). 운영 화면에서 등록, 명단 밖 명의 제출 거부
  "judgeCode": "ANIMAL",
  "adminPin": "0825",
  "rev": 1 // 낙관적 버전. 수신 시 rev 가 낮은 스냅샷은 무시
}
```

- 초기 `judgeCode`/`adminPin` 은 공개 저장소에 있는 값이므로 **행사 전 운영 화면에서 반드시 변경**한다
  (리허설 체크리스트 필수 항목, PIN 은 6자리 이상 권장). 시스템이 강제하지는 않는다.

- `status`: `ready`(대기) → `live`(진행 중, 심사 오픈) → `done`(결과 공개됨)
- **`live` 는 동시에 1경기만** — 경기 시작 시 기존 live 는 ready 로 되돌린다.
- **팀 배치 규칙**: `teams[0]–[1]`, `[2]–[3]`, `[4]–[5]`, `[6]–[7]` 이 R1 대진.
  같은 트랙끼리 인접 배치하도록 운영 화면에 안내 문구 표시.
  (검증 로직 추가 시: 인접 쌍 트랙 불일치 경고)

### 4.2 심사 제출 (심사위원별 개별 레코드)

키: `vote:{matchId}:{judgeSlug}` — **명의별 키 분리로 동시 제출 충돌 방지**

```jsonc
{
  "name": "심사위원 이름",
  "winner": "A" | "B",
  "comment": "선택 입력",
  "videoA": false, // 라운드 2 전용: A팀 영상 대체 여부
  "videoB": false,
  "ts": 1756000000000
}
```

## 5. 상태 전이 / 운영 플로우

```
[팀 8개 입력] → R1-1~4 순차 진행:
  경기 시작(live) → 심사 제출 수집 → 집계 확인 → 승자 지정 + 결과 공개(done)
→ 4경기 완료 시 [라운드 2 랜덤 대진 추첨] 활성화 (Fisher–Yates 셔플로 R2 슬롯 채움)
→ R2 2경기 동일 진행
→ 2경기 완료 시 [결선 대진 확정] 활성화
→ 결선 진행 → 결과 공개 시 스크린이 우승 화면으로 전환
```

- **결과 취소 없음** (2026-08-16 결정): `done` 은 종착 상태다. 결과 공개가 곧 현장 발표라
  롤백해도 발표를 되돌릴 수 없고, 하위 대진 무효화 정책 문제도 함께 사라진다.
  대신 "결과 공개" 버튼에 **확인 다이얼로그를 필수**로 두어 오조작을 사전에 막는다.
  잘못 공개된 경우의 최후 수단은 전체 초기화.
- **백업 모드**: 심사 제출이 0건이어도 운영자가 직접 승자를 지정해 공개할 수 있어야 한다.
  현장 네트워크 장애 시 **운영자 입력만으로 브래킷이 굴러가는 것이 최소 보장선.**
- **전체 초기화**: 상태 + 모든 vote 레코드 삭제. 리허설 후 본 행사 전 사용.
  경기 ID(`R1-1`…)가 재사용되므로 **vote 를 먼저 지우고 상태를 리셋**한다 —
  순서가 반대면 삭제 실패 시 리허설 표가 본 행사 집계에 섞인다.
  심사 코드·운영 PIN·팀 명단·심사위원 명단은 유지 (팀 명단은 옵션으로 비울 수 있게).

## 6. 화면별 명세

### 6.1 스크린 (viewer)

- 상단: 대회 워드마크 + "본선 토너먼트" (기존 브랜드 에셋 적용 영역)
- **라이브 배너**: 현재 live 경기 정보. live 없으면 대기 문구, 결선 done 이면 우승 연출(캐릭터 크게 + 팀명 + 트랙)
- **브래킷**: 3열 (R1 4경기 / R2 2경기 / 결선). 모바일에서는 세로 스택
- **경기 카드**: 팀 2줄(캐릭터·팀명·대학·트랙 배지) + VS. 상태별 표현:
  - `live`: 테두리 강조 + LIVE 배지(점멸)
  - `done`: 승자 하이라이트 + "승" 마크, 패자 dim 처리
  - 대진 미확정 슬롯: "진출팀 대기" 플레이스홀더
- **대결 포커스** (2026-08-18 결정): live 경기가 생기면 대진표 대신 해당 대결을
  크게 — 두 팀 대형 카드 + VS + LIVE. live 가 없으면 대진표로 복귀
- **결과 공개 연출** (2026-08-18 확장): status 가 done 으로 바뀐 순간을 감지해
  (직전 스냅샷과 diff) **투표 오픈 시퀀스** 재생 — "투표를 공개합니다" → 익명 표가
  1초 간격으로 한 장씩 오픈 (실시간 카운터 동기) → 승자 강조 + "진출 확정" →
  대진표 복귀. 표 0건(백업 모드)이면 오픈 단계 생략하고 바로 발표.
  표는 익명 A/B 만, 명의·제출 순서 비공개 (서버 셔플, §3).
  결선이면 시퀀스 종료 후 우승 테이크오버. **`prefers-reduced-motion` 존중**
- **입력 요소 없음.** 폴링으로만 갱신
- 하단 고지: "각 경기 종료 후 즉시 발표 · 부스 투표 8/28(목) 23:59까지"

### 6.2 심사 (judge)

- **입장**: 심사 코드 입력 (대소문자 무시 비교) → 통과 시 **명단에서 본인 이름 선택** (§3)
- **기기 폭 대응** (2026-08-18 확인): 심사위원 기기에 노트북 포함 — 768px 이상에서
  두 팀 카드를 좌우 대형 배치로 전환한다. 폰은 세로 스택 유지
- live 경기 없음 → 대기 화면 + 다음 예정 경기 안내
- live 경기 있음 → 심사 카드:
  - 두 팀 **대형 탭 카드** (캐릭터·팀명·대학·트랙) 중 택1
  - **라운드 2일 때만** 팀별 "시연 장애 → 영상 대체 진행 (실현 가능성 반영)" 체크박스 노출
  - 코멘트 textarea (선택)
  - **간사 대리 입력 모드** 토글 → 켜면 제출 명의 입력 필드 노출, 제출 버튼에 명의 표기
  - 제출 후에도 결과 공개 전까지 수정 재제출 가능 안내
- **라운드별 타이머** (2026-08-19 개정 — 클라이언트 로컬 → **운영 구동 서버 동기**.
  심사위원이 각자 누르는 로컬 타이머는 기기마다 시간이 달라 사실상 장식이었다):
  - 경기 시작 시 해당 라운드 **첫 단계가 자동 시작**, 심사 화면은 **표시 전용**
    (단계 라벨 + 남은 시간, 30초 이하 경고색, 0초 점멸). 단계 전환·재시작은 운영 화면(§6.3)
  - R1: 발표 `5:00` / 공통 Q&A `8:00`
  - R2: 시연 `3:00` / 기술 Q&A `5:00`
  - 결선: 라스트 어필 `1:40` / 심사 합의 `1:40`
  - 서버는 **시작 시각만** 기록하고 남은 시간은 각 기기가 계산 — 폴링 지연(3초)과
    무관하게 남은 시간이 일치한다. **일시정지는 없다** (중앙 시계의 정지 상태 관리는
    당일 운영 복잡도만 높인다 — 재시작으로 갈음). 결과 공개 시 타이머 자동 해제
- 경기가 done 으로 바뀌면 입력 폼 자동 초기화 후 대기 화면 복귀

### 6.3 운영 (admin)

- **입장**: PIN
- 탭 3개:
  - **경기 진행**: 경기별 카드 목록
    - `ready` → "경기 시작"
    - `live` → **타이머 제어**(현재 단계·남은 시간 + 단계 시작/재시작 버튼, §6.2) +
      실시간 집계(4초 폴링 + 수동 새로고침: 팀별 득표수, 다득표 측 자동 강조,
      명의별 제출 내역·코멘트·영상 대체 플래그, **동표 경고**) + 팀별 "결과 공개" 버튼
    - `done` → 결과 표시 + "결과 취소"
    - 하단에 R2 추첨 · 결선 확정 버튼 (조건 미충족 시 disabled)
  - **팀 관리**: 8팀 인라인 편집 (캐릭터, 대학, 팀명, 트랙 select)
    - 캐릭터는 **운영 화면에서 `char_01~80` 그리드를 띄워 직접 선택** (2026-08-17 결정 —
      코드에 학교→캐릭터 매핑 테이블을 두지 않는다. 진출팀 확정 전에 매핑을 박을 수 없고 당일 변경도 자유로워야 함)
  - **설정**: 심사 코드, 운영 PIN, **심사위원 명단 관리(추가·삭제)**, 전체 초기화(확인 다이얼로그 권장), 데이터 공개 범위 고지

## 7. 동기화 / 백엔드 요구사항

> 원본 프로토타입은 Claude 아티팩트 전용 `window.storage`(공유 KV)를 사용했다.
> 자체 스택으로 옮기며 이 부분을 교체한다. **채택: Supabase (관리형 Postgres) + Next.js API 라우트.**

- 공유 KV 또는 그에 준하는 저장소
- **전역 상태**: 단일 문서, 운영자 단독 쓰기, last-write-wins + **rev 버전 가드**
- **vote**: `{matchId}:{judgeSlug}` 단위 개별 레코드 upsert, prefix 조회
- **갱신 전파**: 폴링 3초면 충분. realtime 구독으로 대체하면 결과 공개 연출 반응성이 좋아짐
- **폴링 부하**: 참가자 수백 명이 3초 폴링 → `GET /api/state` 에 CDN 캐시 헤더
  (`s-maxage=2, stale-while-revalidate`) 를 달아 원 서버 부하를 상수로 만든다.
  클라이언트는 rev 가 낮은 스냅샷을 무시 (§4.1)
- 인증은 코드/PIN 수준의 **경량 게이트로 충분** (행사 1일용).
  단, **쓰기 API 는 최소한 서버 측에서 PIN 검증** — 클라이언트 검증만으로는 참가자가 API 직접 호출로 조작 가능
- **현장 네트워크 혼잡 대비**: 저장 실패 시 명시적 에러 표시 + 재시도, 스크린은 **마지막 정상 스냅샷 유지**
- **웹폰트 셀프호스트**: CDN(@import) 의존 제거 — 행사장 네트워크가 불안해도 타이포가 유지돼야 함
- **배포: Vercel** (2026-08-17 결정). GitHub 연동으로 main 머지 시 자동 배포, env 는 대시보드에서 설정.
  오프라인 폴백(운영 노트북 로컬 실행) 시 운영 화면은 노트북 본체에서 연다
  (LAN IP + http 로 붙으면 secure 쿠키가 안 박힘 — env 로 완화 가능)
